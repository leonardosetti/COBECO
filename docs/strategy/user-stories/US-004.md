## 1. História

Como **usuário que esqueceu a senha**,  
eu quero **redefinir minha senha via pergunta de segurança ou token no stdout**,  
para **voltar a acessar minha conta sem suporte manual**.

---

## 2. Critérios de Aceite — Gherkin

### Cenário 1: Recuperação via pergunta de segurança
```gherkin
Dado que sou um usuário cadastrado com pergunta_seguranca = "Nome do primeiro pet?" e resposta hash armazenada
Quando acesso POST /v1/auth/recover com {"nome_usuario": "joao123", "resposta_seguranca": "rex"}
E a resposta confere (bcrypt check)
Então o sistema retorna 200 com {"reset_token": "token_temporario_1h"}
E posso usar esse token no POST /v1/auth/reset-password para definir nova senha
```

### Cenário 2: Recuperação via stdout (modo desenvolvimento)
```gherkin
Dado que RECOVERY_MODE=log no config-env-0001-env-example-v1.0
Quando solicito recuperação para "joao123" (POST /v1/auth/recover com {"nome_usuario": "joao123"})
Então o sistema gera token de reset e imprime no stdout/logs do container backend
E retorna 200 {"message": "Token de recuperação gerado (ver logs)"}
E o token expira em 1 hora
```

### Cenário 3: Resposta de segurança incorreta
```gherkin
Dado que tento recuperar com resposta errada
Quando envio {"nome_usuario": "joao123", "resposta_seguranca": "errada"}
Então retorna 401 "Resposta de segurança incorreta"
E incrementa tentativas (rate limit similar ao login)
```

### Cenário 4: Usuário não existe
```gherkin
Dado que solicito recuperação para usuário inexistente
Quando envio {"nome_usuario": "inexistente"}
Então retorna 200 com mensagem genérica (não vaza existência) "Se o usuário existir, instruções foram enviadas"
```
