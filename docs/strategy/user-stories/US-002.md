## 1. História

Como **usuário cadastrado**,  
eu quero **fazer login com meu nome de usuário (ou email) e senha**,  
para **obter tokens de acesso (JWT) e usar o sistema autenticado**.

---

## 2. Critérios de Aceite — Formato Gherkin

### Cenário 1: Login bem-sucedido
```gherkin
Dado que sou um usuário cadastrado com "nome_usuario" = "joao123" e "senha" = "senha123456"
Quando faço POST /v1/auth/login com {"nome_usuario": "joao123", "senha": "senha123456"}
Então o sistema retorna 200 com JSON {"access_token": "...", "token_type": "bearer"}
E define cookie httpOnly "refresh_token" com JWT refresh (expira 7 dias, SameSite=Strict, Secure em prod)
E o access_token expira em 15 minutos (JWT HS256)
E o refresh_token expira em 7 dias
E posso usar o access_token no header Authorization: Bearer para endpoints protegidos
```

### Cenário 2: Login falha — credenciais inválidas
```gherkin
Dado que sou um usuário cadastrado
Quando faço login com senha incorreta
Então o sistema retorna 401 "Credenciais inválidas"
E não define cookies
E incrementa contador de tentativas falhas para meu IP
```

### Cenário 3: Login falha — usuário não existe
```gherkin
Dado que não existe usuário com "nome_usuario" = "inexistente"
Quando tento login com esse usuário
Então o sistema retorna 401 "Credenciais inválidas" (mesma mensagem por segurança)
```

### Cenário 4: Rate limiting — 6 tentativas em 15 minutos
```gherkin
Dado que faço 6 tentativas de login falhas do mesmo IP em 15 minutos
Quando faço a 7ª tentativa
Então o sistema retorna 429 "Muitas tentativas. Tente novamente em 15 minutos"
E bloqueia temporariamente o IP
```

## 7. Notas Técnicas

- **Access Token:** 15 min, armazenado apenas em memória (JavaScript variable), **não** em localStorage/cookie.
- **Refresh Token:** 7 dias, cookie `httpOnly`, `SameSite=Strict`, `Secure` (apenas HTTPS em prod).
- **Rate Limit:** 6 tentativas por IP / 15 min. Janela deslizante. Armazenado em memória (dict) — aceitável para MVP.
- **Payload JWT:** `{"sub": user_id, "iat": timestamp, "exp": timestamp, "type": "access"}` ou `"type": "refresh"`.
- **Mesma mensagem de erro** para usuário inexistente e senha errada (evita enumeração de usuários).
